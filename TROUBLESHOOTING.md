# Troubleshooting

Real errors hit while building this project, with their cause and fix.
Each entry says where it happened:

- **VM (single-node Slurm):** Lima VM running Ubuntu 24.04 (aarch64) on a MacBook.
- **ASU Sol:** the ASU Sol supercomputer.

| Environment | Error (exact) | Cause | Fix |
|---|---|---|---|
| VM (single-node Slurm) | After installing only the `slurm-client` package, `sinfo` failed with `fetch_config: DNS SRV lookup failed` and `Could not establish a configuration source` | Slurm had no configuration on this VM. With no `slurm.conf` file, the client tries to find a controller through a DNS SRV record, and none exists. | Ran `scripts/setup_vm.sh`, which installs and configures single-node Slurm. Afterwards `sinfo`, `srun` and `sacct` worked. |
| VM (single-node Slurm) | `SyntaxError: invalid character '│' (U+2502)` when running a `python -c "..."` check through `mamba run`. Pasting a block of several commands the same way also gave `remove: The following argument was not expected: │` from `mamba env remove`. | The commands were copied from a terminal window where they had wrapped across lines. The copy included the window's border character `│` (U+2502) and line breaks, which became extra arguments or part of the Python code. The `mamba env remove` failed, so the environment was never removed and the "rebuild" test did not really run. | Type commands by hand or copy them from a plain-text source, one command at a time, and keep `python -c` one-liners short enough not to wrap. Check `mamba env list` afterwards to confirm what really happened. Not a problem with the environment itself. |
| VM (single-node Slurm) | `python -m unittest discover -s tests -v` failed with `ModuleNotFoundError: No module named 'rdkit'`. The traceback paths showed `miniforge3/lib/python3.14/`. | The command ran with Miniforge's base Python (3.14), not the `rdkit-descriptors` environment (Python 3.13 with RDKit). Each command run with the `!` prefix starts a new shell, so a `mamba activate` from an earlier command does not carry over. | Run the command inside the environment explicitly: `mamba run -n rdkit-descriptors python -m unittest discover -s tests -v`. If you get an unexpected `ModuleNotFoundError`, run `which python` to see which Python is in use. |
| VM (single-node Slurm) | `mamba activate rdkit-descriptors` failed with `critical libmamba Shell not initialized` and `'mamba' is running as a subprocess and can't modify the parent shell.` | `mamba activate` has to change the current shell's settings (such as `PATH`), so it only works in a shell that has loaded mamba's shell hook. The shell that runs `!` commands is not an interactive login shell, so the hook was never loaded. Even if it had been, the activation would end when the command finished. | Use `mamba run -n rdkit-descriptors <command>` for single commands and in scripts. In your own interactive terminal, use `conda activate rdkit-descriptors`: the `~/.bashrc` block written by Miniforge's installer loads conda's activation hook, not mamba's. `mamba` still works for installs and for `mamba run`. Do not run the `mamba shell init --root-prefix=~/.local/share/mamba` suggested in the message: Miniforge's root is `~/miniforge3`, not that path. |
